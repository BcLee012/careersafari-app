# CareerSafari 小组整合方案 v1

> 基于 lx、tmj、xrr、lsy 四份方案合并而成，供小组线上讨论定稿。

## 0. 一页结论

**四个人独立收敛到了同一个判断**：这个市场的断裂点不在「缺岗位信息、缺工具」，而在**决策与路径**——学生不知道选什么、不知道差什么、不知道下一步做什么、做完不知道是否该改。

因此四份方案不是竞争关系，而是**同一产品的不同层**：

- **骨架** = lx 的 Decision OS + tmj 的七步闭环 + lsy 的四层数据 → 画像 → 方向 → 差距 → 路径 → 行动 → 复盘
- **血肉** = xrr 的「职业微体验」→ 它是「验证方向」环节的一种形式（tmj 列举的五种低成本验证任务之一）
- **灵魂** = 可验证性（每条建议有依据、可核查）→ **四案均未认真做，这是我们的差异化**

**Demo 定位（9/28）**：不追求大而全，聚焦一刀——**「方向决策 → 差距分析 → 路径生成」的 10 分钟闭环**。

## 1. 四案共识与分歧

### 1.2 分歧（需小组拍板的四个点）

## 2. 产品定义（合并版）

**定位语**（取 lx，与我们的结论一致）：
> 「不是替你决定职业，而是让每个职业选择都有证据、有下一步、有验证方法。」

**产品**：面向大学生（demo 先聚焦管科/工科）的全周期职业决策助手。

**时间轴**（回应 Bruce「大一甚至高考报志愿就可以规划」的判断）：

```
高考报志愿 ── 大一启蒙 ── 大二方向探索 ── 大三实习/深化 ── 大四求职 ── 入职后
   （叙事前端）        （demo 聚焦这里）                        （红海，不做）
```

- **叙事上**：产品从决策最早点介入——「后期求职节点产品已经很多」正是我们的立论，全周期前端是空白
- **Demo 上**：聚焦**大二/大三「方向探索 + 差距 + 路径」**这一刀——全周期中痛点最强、数据最可得、最能演示「以终为始」
- **高考报志愿**：作为故事前端讲，demo 不做（用户变为高中生+家长、每年仅一次窗口、数据需求完全不同、志愿填报已是红海）

## 3. Demo 范围（9/28 硬约束：约 6 天）

### 3.1 用户故事（取 lx，换成我们的主方向）

> 大二管科学生小A：「知道本专业能去供应链/运营/数据分析，但说不清差别，也不知道现在该补什么」
> → 系统基于其专业/课程/技能现状，推荐 3 个方向（每个附依据）→ 小A 选「数据分析师」
> → 展示该方向真实岗位要求与个人差距（已有/待补/待验证）→ 生成分学期准备路径，每步挂依据
> → 标注最大未知项（「是否享受与数据独处」），给出一个低成本验证任务（如两周迷你项目）

### 3.2 功能清单

| # | 功能 | 来源 | Demo 实现 | 优先级 |
|---|---|---|---|---|
| 1 | 个人现状采集 | tmj 2.3.1 / lx ① | 6-8 个问题（专业/年级/课程/技能/兴趣/约束） | **必做** |
| 2 | 方向推荐（3 个，附解释） | lx ② / tmj 2.3.2 | 预置岗位库 + LLM 生成匹配解释 | **必做** |
| 3 | 证据与置信标注 | lx ④ / tmj 2.3.8 | 每条建议标【事实】【推断】【未知】三色 | **必做** |
| 4 | 差距分析 | lx ⑤ / lsy 匹配层 | 已有 / 待补 / 待验证 三类 | **必做** |
| 5 | 路径生成 | lx ⑥⑦ / tmj 2.3.4-5 | 分学期/30-60-90 天路线图 + 里程碑 | **必做** |
| 6 | 依据可点开核查 | 我们的评估 CI（demo 版） | 每条依据附来源链接/出处，可点开验证 | **必做** |
| 7 | 方向同标准比较 | lx ③ / tmj 2.3.3 | 简化为对比表（进入难度/差距/风险） | 有余力做 |
| 8 | 低成本验证任务 | tmj 2.3.3 / xrr 微体验 | 预置 1-2 个任务模板 | 有余力做 |
| 9 | 换目标重生成 | tmj 2.3.7 / lx ⑦ | 演示「改目标→路径自动更新」 | 演示用 |

**明确不做**：简历上传解析、AI 面试、社区、学校管理后台、长期记忆、完整测评体系、大规模爬虫。

### 3.3 数据方案

- **10-20 个精选岗位画像**（取 lx 建议，与 6 天产能匹配），字段规范取 lsy 的职业知识体系：职业名称 → 工作任务 → 核心技能 → 使用工具 → 发展路径 + 薪资区间 + 应届进入方式
- 每个画像挂 **1-3 条真实 JD 引用**（公开可溯源）
- 不做爬虫、不建三层图（入 v2）

## 4. 实现路径

```
用户输入（6-8 问表单）
      ↓
预置岗位画像库（10-20 个，含 JD 引用）  ← 人工整理，非爬虫
      ↓
LLM（DeepSeek / Kimi / Stepfun）生成：方向推荐 + 匹配解释
      ↓
LLM 生成：差距分析（已有/待补/待验证）+ 分学期路径
      ↓
程序层：依据挂载（每条建议关联画像字段 + JD 链接）+ 三色标注
      ↓
Streamlit 界面展示 + 演示「换目标重生成」
```

- **技术栈**：Python + LLM API + Streamlit，全部本地运行
- **关键工程原则**（取 xrr）：AI 不自由创造事实——岗位要求来自预置画像，LLM 只负责解释与组合；每条输出必须能回溯到画像字段
- **评估（demo 版）**：依据可点开 + 内部走查（3 人交叉检查 10 条输出的依据是否真实）；**完整评估 CI 五项核查入 v2**
