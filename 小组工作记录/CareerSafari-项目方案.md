# CareerSafari 项目方案（定稿）

> **这份文档解决三件事**：我们在做什么、你负责什么、六天怎么走。
> 看完这份就够开工，不需要读其他资料。

---

## 一、我们要做什么

**一句话**：帮大三学生（暑假要投实习、还没定方向的）想清楚三件事——**该往哪个方向走、现在差什么、接下来两周做什么。**

```
回答 6-8 个问题（专业、年级、学过什么、会什么、兴趣、约束）
        ↓
系统按固定规则打分 → 给出 3 个候选方向，每个附匹配依据
        ↓
用户选一个方向
        ↓
看到差距：已有 / 待补 / 待验证
        ↓
拿到一项两周微任务——它要验证你自己的哪个假设
        ↓
每一句关键结论都能点开看证据来源；
不确定的明确标「未知」或「团队判断」，不糊弄
```

**演示故事（9/28 用这个）**：
> 大三学生小A，暑假要投实习，在数据分析、运营、供应链分析之间犹豫，不知道现在开始补什么来得及。
> → 回答 8 个问题 → 系统按规则打分给出 3 个方向，供应链分析排第一（并说明分数由什么构成）
> → 小A 选「供应链分析」→ 看到差距：已有（Excel/线性代数）/ 待补（SQL、库存优化基础）/ 待验证（是否接受与数据独处）
> → 拿到两周微任务：「用公开数据集做一个进销存分析并写 300 字结论」——说明它要验证的假设是「是否享受从数据里找答案」
> → 每条结论可点开看证据编号和来源；没把握的地方明确标出来

**不做**：简历优化、模拟面试、投递追踪——那些产品已经很多了。我们做「求职之前」。

## 二、为什么是这个方向

### 2.1 五位成员各自调研，得出了同一个结论

**学生最痛的不是「找不到岗位信息」，而是「不知道选什么、不知道差什么、不知道下一步做什么」。**

支撑数据：

| 数据 | 来源 |
|---|---|
| 仅 **22.9%** 的大学生有明确职业规划，77.1% 存在职业认知滞后 | 中国青少年研究中心 |
| 没拿到 Offer 的毕业生中 **36.2%** 是因为「过度迷茫、不清楚自身适配方向」，连续多年排第一 | 智联招聘《2024 大学生就业力调研报告》 |
| **64.8%** 的大学生表示不清楚市场情况 | 中国青年报社社会调查中心 |

### 2.2 竞品判断（用可证伪的表述）

> 在我们调研的 11 个代表性产品中，**较少有产品同时提供「方向推荐 + 证据级别标注 + 可验证的下一步行动」**；大多数产品的火力集中在求职执行环节（简历、投递、面试）。

（详细竞品对比见 `研究资料/竞品分析报告.md`。用可证伪的表述而不是「没人做」——后者一个反例就塌。）

### 2.3 我们的位置

**每条建议都有依据、能点开核查；不确定的明确说不确定。**

通用 AI 也能聊职业规划，但它说得漂亮却没法验证，甚至会编。学术界已经有证据：RCT 显示 AI 生涯智能体反而**增加**决策疑虑；79% 的用户会听从 AI 建议但没有持续改善。**「让不可验证的智能变得可验证」就是我们的位置。**

## 三、产品怎么工作

### 3.1 三条硬约束（立足点，不是口号）

1. **每条岗位事实在资料库里都有唯一编号**；AI **只能引用已存在的编号**
2. **资料库里没有的，AI 必须说「未知」或标「团队判断 + 置信度」**——不许自己编，也不许生成链接
3. **程序在展示前自动检查**：出现资料库外的说法就拒绝显示

### 3.2 推荐机制：规则先于模型

排名由**代码里的确定性规则**决定（技能匹配、兴趣倾向、约束符合、年级匹配四个维度打分），AI 只负责解释分数构成和生成行动建议。

- 好处：可复现、可测试、可解释——「为什么推荐这个」有真实答案
- 诚实交代：**规则权重本身是团队判断**，标为「团队判断 + 置信度」，不伪装成客观

### 3.3 功能分两层（砍单规则因此自洽）

**保底链路 5 步**（D4 没跑通时唯一要保的）：

| # | 环节 | 说明 |
|---|---|---|
| 1 | 现状采集 | 6-8 题，每题映射一个评分字段或未知项 |
| 2 | 规则评分 + Top 3 | 确定性打分，AI 只解释 |
| 3 | 选方向 + 差距分析 | 已有 / 待补 / 待验证 |
| 4 | 两周微任务 | 说明它要验证的假设 |
| 5 | 证据类型 + 来源 ID | 每句关键结论带证据标识，可点开 |

**增强项**（保底跑通后按序加）：换方向重生成 → 方向同标准比较表 → 分学期完整路径（演示用预置案例展示）→ 界面三色/分级呈现。

### 3.4 证据合同（按结论类型分，四类）

| 结论类型 | 证据来源 | 展示标注 |
|---|---|---|
| 岗位要求（技能/证书/门槛） | 外部来源，**每条能力结论至少 2 条**，注明适用范围和日期 | 事实·可溯源（带 ID） |
| 推荐理由 | 用户回答 + 评分规则（规则本身可见） | 事实·规则 |
| 行动建议（两周任务、学习建议） | 团队判断，显示假设与置信度 | 团队判断 |
| 用户自述 | 用户明说的信息，独立存储与标注 | user_stated |

**原则**：宁可少写，不可编造。「团队判断」不是羞耻，是诚实——标出来，产品才可信。

## 四、数据契约（tmj 在 D1 交付）

这份契约同时是**验收标准**——内容块交付的资料不合契约即返工，避免 D3/D4 技术块才发现对不上。

| 字段 | 类型 | 必填 | 允许值 | 说明 |
|---|---|---|---|---|
| `direction_id` | string | 是 | DIR-001 起 | 方向唯一编号 |
| `name` | string | 是 | — | 方向名称 |
| `cap_id` | string | 是 | DIR-001-CAP-01 | 能力唯一编号 |
| `cap_name` | string | 是 | — | 能力名称 |
| `level` | 枚举 | 是 | 必备 / 加分 / 了解 | 重要性 |
| `evidence_ids` | 列表 | 二选一 | EV-xxx | 要么挂 ≥2 条证据，要么 `status=unknown` |
| `scope_note` | string | 是 | — | 适用范围，如「制造业与零售业」 |
| `ev_id` | string | 是 | EV-001 起 | 证据唯一编号 |
| `ev_type` | 枚举 | 是 | external / team / **user_stated** | 外部来源 / 团队判断 / 用户自述（为 v2 预留） |
| `source_url` | string | external 必填 | — | 来源链接 |
| `captured_date` | 日期 | 是 | YYYY-MM-DD | 采集日期 |
| `excerpt` | string | 是 | — | 原文摘录，≤100 字 |
| `status` | 枚举 | 否 | unknown | 无证据时必须填，不许留空 |

**缺失处理规则**：
- 一条能力找不到 ≥2 条证据 → `status` 填 `unknown`，界面显示「待验证」，**不允许填猜测**
- 证据没有可用链接 → `ev_type` 改为 `team`，并在 `excerpt` 写明判断依据

**资料范围**：3-4 个相近方向（建议：数据分析、运营、供应链分析、商业分析），每方向 5-8 条高质量、可追溯的能力证据。

## 五、技术实现

```
用户 6-8 问 → 映射为评分字段
                  ↓
       确定性规则打分（代码，可复现）→ Top 3
                  ↓
       AI 解释匹配理由（只能引用证据 ID）
                  ↓
       用户选择 → AI 生成差距分析 + 两周微任务
                  ↓
       程序校验层：扫描所有引用 ID 是否存在于库 → 不存在则拒绝展示
                  ↓
       Streamlit 展示（证据类型 + ID 可见）
```

- **技术栈**：Python + LLM API（DeepSeek / Kimi / Stepfun）+ Streamlit，全部本地运行
- **D4 额外交付「环境可复现」文档**：依赖清单、一键启动脚本、API key 申请方式——**每个人都要能自己跑一遍**，否则讨论退化成看一个人表演
- **降级方案**：D5 前备一份无模型的预置案例（小A 的完整走查结果）。用途：组员自己试用时 API 限流或额度耗尽，不阻塞讨论
- **交互日志（现在就要做）**：从第一天起按 `{输入, 检索到的证据 ID, 模型输出, 校验结果, 用户反馈}` 记录每次交互。它既是未来训练的原料，也是当下最好的评估数据集

## 六、分工：三块，块内自己协调，块间只交三次东西

**分组原则**：按「需要多频繁对齐」分，不按工作类型分。需要频繁讨论的人放同一块，块间只交接成品。

```
内容块：tmj + lsy + 第6位（在职，异步）   →  证据库（3-4 方向 × 每方向 5-8 条）
技术块：Bruce + xrr                      →  能跑的应用（规则评分 + 引用约束 + 校验层 + 界面）
表达块：lx                               →  演示脚本 + 访谈 + 用户测试 + 全员走查
```

| 成员 | 块 | 你要交付什么 |
|---|---|---|
| **tmj** | 内容 | **D1 数据契约**（第四节那张表 + 一个完整样例）+ 2 个样板方向 |
| **lsy** | 内容 | 按契约填 3-4 个方向 × 每方向 5-8 条证据；每条能力至少 2 个来源 |
| **第 6 位（在职）** | 内容 | 异步三件：① 你的职业路径经历 1 份 ② **D2 逐条审核 tmj 的 2 个样板**（写清改了什么、为什么）③ 演示时讲 3 分钟「真实从业者怎么说」 |
| **Bruce** | 技术 | AI 接入 + 校验层 + 主链路装配（**集成总负责**）；D4 交环境文档 |
| **xrr** | 技术 | 输出协议与质量门槛（证据编号规则、提示词引用约束、校验规则）+ Streamlit 界面 |
| **lx** | 表达 | 保底版演示脚本 + 2-3 位就业中心老师访谈 + 用户测试 + 组织全员走查 |

**为什么第 6 位这样安排**：你的任务都不需要实时协作，D2 才开始需要你；而且你在职的经历正是我们最缺的「真实路径」素材——演示时有真实从业者说一句话，比我们一群学生自说有说服力得多。

**为什么 xrr 在技术块而不是做「事后检查」**：把严谨的证据标准直接设计进数据格式和提示词里，比做完了再挑错有效——标准和生产是同两个人，不存在「标准晚于产出」。

### 块间只交接三次（其他时间互不打扰）

| 时点 | 交什么 | 从 → 到 |
|---|---|---|
| **D1** | 数据契约（tmj 出，Bruce 花 10 分钟确认「这些字段我的程序用得上」） | 内容 → 技术 |
| **D3** | 填好的证据库（3-4 方向 × 每方向 5-8 条，含来源链接） | 内容 → 技术 |
| **D5** | 可跑的应用（技术块交，lx 拿去给非组员做测试） | 技术 → 表达 |

**每个交付物长什么样、有没有样例可抄 → 看 `任务样例手册.md` 里你那节。**

| 时点 | 触发条件 | 动作 |

| D4 | 保底 5 步未跑通 | 冻结一切增强项，只保主链路 |

### 用户测试怎么做（D5，lx 主导）

- **不解释产品、不代填、不提示**——测试者必须能自己开始
- 记录三件事：完成率 / 卡在哪 / 能否说出「方向 + 不确定什么 + 两周做什么」
- D6 只修影响这三件事的问题，其余记入 v2

### Demo 是给组员讨论用的，不是给评委打分的

目标不是「演示得漂亮」，是「**每个人都能自己判断这个方案可不可行**」。所以：D4 必须交环境文档（每人能自己跑一遍）；D6 是全员走查不是彩排；降级方案用于防 API 限流而不是防现场翻车。

## 八、商业模式与风险（标注：未验证假设）

**B2B2C（学生处/教务 + 家长）是假设，不是计划。** 竞品报告里「B2B2C 是唯一被验证路径」是对有销售能力的公司（Huntr、Leland）成立，对我们不成立；且国家平台「智慧小业」免费且政策推动，高校预算竞争更复杂。

**本周验证动作**：lx 访谈 2-3 位高校就业指导中心老师/辅导员，问三件事——现在用什么工具、最缺什么、愿不愿意试用学生做的原型。

**风险与责任边界**：

| 风险 | 应对 |
|---|---|
| 重大决策责任 | 定位「决策材料提供者」，不替用户决定；建议附依据与备选 |
| 心理危机 | 识别明显危机信号时给转介路径（学校心理中心等） |
| 谄媚与过早决策背书 | 提示词层面防「为好听而背书」；v2 入评估 CI |
| 数据合规 | 全本地处理；JD 爬取控制频率（v2 才涉及） |
| L2 依据不可溯源 | 分级标注 + 团队判断带置信度，不挂假依据 |

## 九、v2 路线（Demo 之后）

| 优先级 | 内容 | 理由 |
|---|---|---|
| **第一位** | **长期记忆 / 个人档案** | 不是差异化功能，是**必要条件**：我们讲「全周期」，没有跨时间档案这句话就是空话 |
| 第二位 | 分学期路径生成（证据守得住尺度上） | Demo 里只能用预置案例展示 |
| 第三位 | 节点横向扩展（大一专业认知、大四求职） | 产品从单节点工具变成节点序列 |
| 第四位 | 评估 CI 系统化（引用违规率指标、多模型基准、拒答策略） | AI 工程深度的主线 |

**长期记忆的设计纪律**（和职悟空「长期记忆」的差别）：用户自述作为独立证据类型；每条记忆带来源与时间；档案更新必须用户确认；允许关闭与删除。**它做「记住你」，我们做「记住你，且每条记忆可追溯」。**

**关于「把数据用于训练」**：现在和 v2 都不要碰微调（样本量不够，且违反数据最小化）。v2 该做的是**上下文注入**（档案按任务门控进 prompt，95% 收益、零训练成本）；SFT 与偏好优化是 v3，且原料必须是合成数据 + 人工对比标记，不能拿真实用户对话直接训。

## 附录 A：这份方案被怎么审查过

两轮独立审查，主要修正如下（保留记录是为了让各位知道结论经受过什么）：

**第一轮（第一性原理重审，修正我们自己）**：
1. 「错位竞品」原来赌的是对手行为——改为只保留两个有证据的事实，不再声称「平台没动力做深」，不再把「竞品少」当机会
2. 「目标反推」与用户症状矛盾（用户缺的就是目标）——改为主入口做**方向发现**，反推降为引擎
3. 「全周期陪伴」押的是全行业未解的指标——降为叙事层，产品承诺改为单节点做深
4. 「可验证性」原本混为一谈——拆成产品层（给用户看）和工程层（我们的可信度）
5. 分工从 11 个协调点收敛为 3 个；Done 标准从「功能跑通」改为「非组员用户能走完并说出三件事」

**第二轮（外部评审，11 条全部采纳 + 2 条补充）**：
1. 「AI 不许编造」原来只是原则——落成证据 ID + 引用约束 + 生成后校验的机制

## 附录 B：AI 工程体现在哪（防问倒）

**不要把我们说成「做了个数据库然后查表」**：

1. **库外怎么表现才是主战场**。证据库只覆盖 3-4 个方向，用户一定会问出库外的问题（跨专业、地域、家庭约束）。**查不到时不说谎，比查得到难得多**——这正是全行业没解决的事。
2. **约束一个会编的模型，比放任它编更难**。证据 ID + 引用约束 + 生成后校验是工程活；放任模型自由生成才是调包。
3. **评估是最硬的证据**。同一问题，我们的系统 vs 裸 DeepSeek/Kimi/Stepfun，逐条标出谁越界、谁引用了不存在的来源。

**主动说明的立场**（别被问出来）：不微调（数据量不够，也没必要）；不做多 Agent（单链就够）；用了检索但比常规 RAG 更严格（证据 ID + 生成后校验）。

**诚实的边界**：6 天 demo 尺度上 AI 工程深度有限——demo 证明「价值主张可验证」，模型层深度是 v2 主线。这句话主动说，是加分项。
