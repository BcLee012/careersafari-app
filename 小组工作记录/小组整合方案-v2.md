# CareerSafari 小组整合方案 v2

> 基于 lx、tmj、xrr、lsy、Bruce 五份思路合并而成，供小组线上讨论定稿。

## 0. 一页结论

**五位成员独立收敛到了同一个判断**：这个市场的断裂点不在「缺岗位信息、缺工具」，而在**决策与路径**——学生不知道选什么、不知道差什么、不知道下一步做什么、做完不知道是否该改。

五份思路不是竞争关系，而是**同一产品的不同层**，且 Bruce 的提案提供了把五者统一起来的**组织架构——关键节点**：

- **架构（Bruce）**：产品 = 一条全周期时间轴上的**关键节点序列**，每个节点提供该时点的决策支持
- **骨架（lx + tmj + lsy）**：每个节点内部跑同一套引擎——画像 → 方向 → 差距 → 路径 → 行动 → 复盘
- **血肉（xrr）**：「验证方向」环节的体验式形式（低成本验证任务的一种）
- **灵魂（全员共识 + 我们的结论）**：可验证性——每条建议有依据、可核查

**Demo 定位（9/28）**：不做「大而全的全周期」，而是**把一个节点做深**——大二/大三的「方向探索 + 差距 + 路径」。全周期不是 demo 的内容，是 demo 的叙事。

## 2. 产品定义：节点化的全周期职业决策助手

### 2.1 核心架构（Bruce 提案的工程化）

产品不是功能列表，而是**一条时间轴上的关键节点序列**。每个节点有统一结构：

```
触发条件（年级/时间/事件）
   ↓
该节点的核心决策（选什么）
   ↓
节点引擎（tmj 七步闭环的微循环）：
   认识自己 → 了解职业 → 形成选择 → 验证方向 → 规划路径 → 行动 → 复盘
   ↓
节点资源（该时点可用的校内/公开资源——Bruce 的「资源梳理」）
   ↓
复盘输出（认识变化 + 下一步）
```

节点序列（v1 定义，demo 只做其中一个）：

| 节点 | 时点 | 核心决策 | Demo |
|---|---|---|---|
| 高考报志愿 | 高三暑假 | 选什么专业/学校 | ❌ 叙事前端 |
| 专业认知与分流 | 大一 | 是否转专业/如何理解本专业 | ❌ |
| **方向探索** | **大二/大三** | **往哪个职业方向走、差什么、怎么补** | ✅ **demo 聚焦** |
| 实习与深化 | 大三 | 投什么实习、补什么证据 | ❌ |
| 求职冲刺 | 大四 | 投什么岗位、offer 怎么选 | ❌ 红海，明确不做 |
| 入职后调整 | 毕业后 | 试用期/首次转型 | ❌ |

### 2.2 为什么这个架构成立（三个理由）

1. **全周期不是空话**：它是节点的集合。demo 是把一个节点做深，v2 是横向扩展节点——**扩展路径清晰，不是无限堆功能**
2. **每个节点数据结构统一**：知识库按节点组织，内容生产可按节点分工（见第 5 节），在职成员也能低协调参与
3. **结构性避开红海**：我们做「节点」，求职只是最后一个节点；且越早的节点（报志愿、分流、方向探索）竞品越少——与 Bruce 的判断一致

### 2.3 定位语

> 「不是替你决定职业，而是让每个职业选择都有证据、有下一步、有验证方法。」（取 lx）

## 3. Demo 范围（9/28 硬约束：约 6 天）

### 3.1 用户故事

> 大二管科学生小A：「知道本专业能去供应链/运营/数据分析，但说不清差别，也不知道现在该补什么」
> → 系统基于其专业/课程/技能现状，推荐 3 个方向（每个附依据）→ 小A 选「数据分析师」
> → 展示该方向真实岗位要求与个人差距（已有/待补/待验证）→ 生成分学期准备路径，每步挂依据
> → 标注最大未知项（「是否享受与数据独处」），给出一个两周迷你项目作为低成本验证任务

### 3.2 功能清单（按节点引擎展开）

| # | 功能 | 对应节点引擎步骤 | 来源 | 优先级 |
|---|---|---|---|---|
| 1 | 个人现状采集（6-8 问） | 认识自己 | tmj 2.3.1 / lx ① | **必做** |
| 2 | 方向推荐 3 个（附解释） | 形成选择 | lx ② / tmj 2.3.2 | **必做** |
| 3 | 证据与置信标注（事实/推断/未知） | 信任保障 | lx ④ / tmj 2.3.8 | **必做** |
| 4 | 差距分析（已有/待补/待验证） | 规划路径 | lx ⑤ / lsy 匹配层 | **必做** |
| 5 | 分学期路径生成 | 规划路径 | lx ⑥⑦ / tmj 2.3.4-5 | **必做** |
| 6 | 依据可点开核查 | 信任保障 | 我们的评估 CI（demo 版） | **必做** |
| 7 | 方向同标准比较 | 形成选择 | lx ③ / tmj 2.3.3 | 有余力 |
| 8 | 低成本验证任务 | 验证方向 | tmj 2.3.3 / xrr 微体验 | 有余力 |
| 9 | 换目标重生成 | 复盘调整 | tmj 2.3.7 / lx ⑦ | 演示用 |

**明确不做**：简历上传解析、AI 面试、社区、学校后台、长期记忆、完整测评、大规模爬虫、其他节点。

### 3.3 数据方案

- **10-20 个精选岗位画像**（lx 建议，与 6 天产能匹配），字段取 lsy 的职业知识体系：职业名称 → 工作任务 → 核心技能 → 使用工具 → 发展路径，外加薪资区间、应届进入方式、常见专业来源
- 每个画像挂 **1-3 条真实 JD 引用**（公开可溯源）
- 第 6 位在职成员提供 **1-2 个本行业岗位画像**及其真实路径案例（双源数据中的「路径侧」）
- 不做爬虫、不建三层图（入 v2）

## 4. 实现路径

```
用户输入（6-8 问表单，节点=大二方向探索）
      ↓
预置岗位画像库（10-20 个，含 JD 引用）  ← 人工整理，非爬虫
      ↓
LLM（DeepSeek / Kimi / Stepfun）生成方向推荐 + 匹配解释
      ↓
LLM 生成差距分析（已有/待补/待验证）+ 分学期路径
      ↓
程序层：依据挂载（每条建议关联画像字段 + JD 链接）+ 三色标注
      ↓
Streamlit 展示 + 演示「换目标重生成」
```

- **技术栈**：Python + LLM API + Streamlit，全本地运行
- **关键工程原则**（取 xrr）：AI 不自由创造事实——岗位要求来自预置画像，LLM 只负责解释与组合；每条输出必须可回溯到画像字段
- **评估（demo 版）**：依据可点开 + 3 人交叉走查 10 条输出的依据真实性；完整评估 CI 五项核查入 v2

## 5. 分工建议（6 人 × 6 天，含在职成员照顾方案）

| 成员 | 角色 | 核心交付 | 每周投入 | 说明 |
|---|---|---|---|---|
| **Bruce** | 总体架构 + AI/评估 | 技术方案、LLM 接入、依据挂载逻辑 | 6-8h | 与正式文档对齐 |
| **lx** | 产品 owner | demo 脚本、用户故事、功能优先级、演示流程 | 6-8h | 其 demo 定义最工程化 |
| **tmj** | 节点知识库 owner | 画像字段规范、10-20 个画像内容、来源审核记录 | 6-8h | 其数据框架最完整 |
| **xrr** | 评估与验证 owner | 输出质量标准、依据核查清单、走查方案、演示话术的「证据边界」 | 6-8h | 其方法论最严谨 |
| **lsy** | 数据 + 前端支撑 | JD 引用整理、画像填充、字段一致性检查、Streamlit 界面 | 6-8h | 其知识体系结构最清晰 |
| **第 6 位（在职）** | **从业者视角（异步）** | ① 本人职业路径案例 1 份 ② 1-2 个本行业岗位画像的真实性审核 ③ 演示时 3 分钟「真实从业者怎么说」 | **2-3h，异步，不占关键路径** | 见下方说明 |

### 5.1 为什么这样安排第 6 位

在职成员时间不可控，因此设计原则是**「不占关键路径 + 用其独特资产 + 异步可交付」**：

1. **不占关键路径**：其交付物（路径案例、真实性审核）在 D3-D5 才被需要，前期不等他
2. **用其独特资产**：在职 = 我们「路径侧」数据的天然来源——他的真实职业路径是产品里「过来人怎么说」的证据层，也是演示时最有说服力的一段
3. **异步可交付**：三项任务都不需要实时协作，一份文档/一次审核/一段话术即可

### 5.2 六天计划

| 天 | 里程碑 | 砍单线 |
|---|---|---|
| D1 | 方案定稿 + 分工确认 + 画像字段规范冻结 | — |
| D2-D3 | 10-20 个岗位画像 + JD 引用；demo 脚本定稿；向在职成员发出任务包 | 画像先保 6-8 个核心方向 |
| D4 | 核心链路跑通（输入→推荐→差距→路径） | **砍功能 7/8，只保 1-6** |

**铁律**：D4 结束时若核心链路未跑通，冻结所有新功能，全力保「输入→推荐→差距→路径」主链路可演示。
