# CareerSafari 小组整合方案 v4

> 基于五份成员方案合并，经第一性原理重审与外部评审修正。定稿版。

## 0. 一页结论

**五位成员独立收敛到同一判断**：市场的断裂点不在「缺岗位信息、缺工具」，而在**决策与路径**。

**v4 的核心变化**：把「有依据、可核查、不瞎编」从一句原则**变成一套机制**。此前它是口号——没有任何东西在阻止模型在演示当天编造一个资料库里不存在的要求，而那会让我们全部的差异化说法当场失效。

**最小产品定义（冻结版）**：

```text
目标用户：大三、暑期实习前、在数据类/运营类/供应链类方向之间犹豫、尚未定方向的学生
资料范围：3-4 个相近方向（建议：数据分析、运营、供应链分析、商业分析），
          每个方向 5-8 条高质量、可追溯的能力证据
输入：6-8 题，且每题必须对应一个评分字段或一个「未知项」
输出：
  1. 三个方向 + 规则化匹配理由（不是模型凭感觉选）
  2. 一个选定方向的「已有 / 待补 / 待验证」
  3. 一项两周微任务，说明它要验证用户的哪个假设
  4. 每一句关键结论的证据类型与来源 ID
```

## 2. 产品定义 v4

### 2.1 与 v3 的实质差异

| | v3 | v4 |
|---|---|---|
| Demo 终点 | 分学期准备路径（每步挂依据） | **一项两周微任务 + 它要验证的假设** |
| 分学期路径 | 必做 | 增强项（演示用预置案例展示，不要求实时生成） |
| 推荐机制 | 未定义 | 规则评分选 Top 3，AI 只解释评分结果 |
| 乱编防护 | 原则（"AI 只负责解释和组合"） | 机制（证据 ID + 引用约束 + 生成后校验） |

**为什么把终点从「路径」改为「微任务」**：分学期路径的每一步都挂可溯源证据，在 6 天内做不到可信（L2「哪门课能学会 SQL」本身缺权威来源）；而「两周微任务」是同一个价值（下一步做什么）在**证据合同守得住的尺度上**的版本，且更可验收。路径生成是 v2 主线，Demo 用预置案例说明产品走向。

### 2.2 规则评分（推荐机制）

```
用户 6-8 个回答 → 映射为评分字段（技能匹配度/兴趣倾向/约束符合度/年级匹配）
                    ↓
       对 3-4 个候选方向分别打分（确定性规则，可复现）
                    ↓
       取得分最高的 3 个 → AI 只负责：解释每个分数由什么构成、生成行动建议
```

- **规则先于模型**：排名由代码决定，不由模型决定——可复现、可测试、可解释
- **规则权重本身标为「团队判断 + 置信度」**（证据合同第四类），不伪装成客观
- AI 的职责收缩为「解释 + 生成建议」，这正是它能可靠做好的部分

### 2.3 两层功能（消除砍单矛盾）

**保底链路（D4 未跑通时唯一要保的 5 步）**：

| # | 环节 | 说明 |
|---|---|---|
| 1 | 现状采集 | 6-8 题，每题映射一个评分字段或未知项 |
| 2 | 规则评分 + Top 3 | 确定性打分 + AI 解释匹配理由 |
| 3 | 选择方向 + 差距分析 | 已有 / 待补 / 待验证 |
| 4 | 两周微任务 | 说明它要验证的假设 |
| 5 | 证据类型 + 来源 ID | 每句关键结论带证据标识 |

**增强项（跑通后再加，按此顺序）**：换方向重生成 → 方向同标准比较表 → 分学期路径（预置案例）→ 界面三色/分级呈现。

> 砍单规则随之自洽：**D4 结束时若保底链路 5 步未跑通，冻结增强项；若保底仍未通，才启动降级方案（见 6.3）。**

### 2.4 约束机制（核心价值的技术落地）

三条硬约束，缺一则「不瞎编」仍是空话：

1. **结构化证据库**：每条能力证据有唯一 ID + 适用范围 + 日期 + 来源链接；单条能力结论至少挂 2 条证据
2. **引用约束**：模型只能引用已存在的证据 ID；**输出中出现资料库外的来源链接或事实，程序直接判不合格**
3. **无证据必须出声**：资料库没有的信息，模型必须输出「未知」或标「团队判断 + 置信度」，不允许生成链接、不允许沉默带过

配套：**生成后校验层**——程序在展示前扫描输出，检查所有引用 ID 是否存在于库中，不存在则拒绝展示。

### 2.5 证据合同（四类，按结论类型分）

| 结论类型 | 证据来源 | 展示标注 |
|---|---|---|
| 岗位要求（技能/证书/门槛） | 外部来源，≥2 条，注明适用范围与日期 | 事实·可溯源（带 ID） |
| 推荐理由 | 用户回答 + 评分规则（规则本身可见） | 事实·规则 |
| 行动建议（两周任务、学习建议） | 团队判断，显示假设与置信度 | 团队判断 |
| 评分规则权重 | 团队设定，标明置信度 | 团队判断 |

**原则**：宁可少写，不可编造；「团队判断」不是羞耻，是诚实——把它标出来，产品才可信。

> **v2 补充**：`user_stated`（用户自述）作为独立证据类型已写入 D1 数据契约。个人档案（长期记忆）为 v2 第一位——理由是**必要性**：我们宣称「全周期」，没有跨时间档案这句话就是空话。相关数据模型见 `任务样例手册.md` 附录。

## 3. 数据契约（D1 交付物，替代此前的「字段表」）

D1 由 tmj 产出、Bruce 花 10 分钟确认的**数据契约**必须包含：

| 项 | 内容 |
|---|---|
| 字段名与类型 | 如 `skill_name: string`、`evidence_ids: list[string]` |
| 必填项 | 哪些字段缺失则该条证据不可用 |
| 允许值 | 如证据类型只能是 `external` / `team` |
| 证据格式 | ID 规则、适用范围、日期、来源链接的写法 |
| 缺失时处理 | 某能力无证据时，记录为 `unknown` 而非猜测填充 |
| 完整样例 | 一个填好的 JSON 或表格样例（技术块据此开发） |

**这份契约同时是验收标准**：内容块交付的画像库，字段不合契约即返工——避免 D3/D4 技术块才发现对不上。

## 4. Demo 用户故事（v4）

> 大三学生小A，暑假要投实习，在数据分析、运营、供应链分析之间犹豫，不知道现在开始补什么来得及。
> → 回答 8 个问题（专业、学过什么、会什么、兴趣、约束…）
> → 系统按固定规则打分，给出 3 个方向：供应链分析（技能匹配度最高）、运营、商业分析——**每个方向说明分数由什么构成**
> → 小A 选「供应链分析」→ 看到差距：已有（Excel/线性代数）/ 待补（SQL、库存优化基础）/ 待验证（是否能接受与数据独处）
> → 拿到一项两周微任务：「用公开数据集做一个进销存分析并写 300 字结论」——**说明它要验证的假设是「是否享受从数据里找答案」**
> → 每条结论可点开看证据 ID 与来源；不确定的地方明确标「未知」或「团队判断」

## 5. 实现路径

```
用户 6-8 问 → 评分字段映射
                  ↓
       确定性规则打分（代码，可复现）→ Top 3
                  ↓
       AI 解释匹配理由（只能引用证据 ID）
                  ↓
       用户选择 → AI 生成差距分析 + 两周微任务
                  ↓
       程序校验层：扫描所有引用 ID 是否存在于库 → 不存在则拒绝展示
                  ↓
       Streamlit 展示（证据类型 + ID 可见）
```

- **技术栈**：Python + LLM API（DeepSeek/Kimi/Stepfun）+ Streamlit，全本地
- **工作量提示**：约束机制比 v3 增加约 4-6 小时（证据 schema、ID 管理、校验层）——已通过「界面呈现降为增强项」抵消
- **降级路径**：若 API 在演示当天不可用，走预置案例完整走一遍（见 6.3）

### 6.2 用户测试脚本（D5）

- **不解释产品、不代填、不提示**——测试者必须能独立开始
- 记录三个指标：**完成率 / 卡住点 / 是否能说出三件事**（我被推荐的方向、我还不确定什么、接下来两周做什么）
- D6 只修影响这三个指标的问题，其余记录进 v2

**验收条件**：
> 对预设用户小A，系统不得输出资料库外的岗位事实；测试者无需解释即可说清「我为什么被推荐这个方向、我还不确定什么、接下来两周做什么」。

### 6.3 降级方案（D6 彩排必做）

- 准备一份**无模型的预置案例**（小A 的完整走查结果，含全部证据 ID）
- D6 彩排必须包含一次「拔网线」演练：断网状态下用预置案例完成演示
- 目的：API 故障、配额用完、现场网络问题时，Demo 的价值主张依然可完整呈现
