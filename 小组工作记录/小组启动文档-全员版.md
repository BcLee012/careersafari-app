# CareerSafari 小组启动文档

> **这份文档的目的**：让每位成员看完就知道——我们在做什么、为什么这么做、你个人下一步要交付什么。
> 不需要读其他资料。有异议请在讨论会上直接提。

---

## 一、我们在做什么（30 秒版）

做一个叫 **CareerSafari** 的 AI 产品：帮大学生想清楚三件事——

> **我该往哪个职业方向走？我现在差什么？接下来两周该做什么？**

**关键区别**：我们**不做**求职工具（改简历、模拟面试、投递那类），那种产品已经很多了。我们做**求职之前的方向决策**。

**9 月 28 日前**，做出一个能跑的 10 分钟演示。

---

## 二、为什么是这个方向（3 分钟版）

我们五位成员各自调研，**得出了同一个结论**：

**学生最痛的不是"找不到岗位信息"，而是"不知道选什么、不知道差什么、不知道下一步做什么"。**

支撑数据：

| 数据 | 来源 |
|---|---|
| 仅 **22.9%** 的大学生有明确职业规划，77.1% 存在职业认知滞后 | 中国青少年研究中心 |
| 没拿到 Offer 的毕业生中 **36.2%** 是因为"过度迷茫、不清楚自身适配方向"，连续多年排第一 | 智联招聘《2024 大学生就业力调研报告》 |
| **64.8%** 的大学生表示不清楚市场情况 | 中国青年报社社会调查中心 |

而在我们调研的 11 个代表性产品中，**较少有产品同时提供「方向推荐 + 证据级别标注 + 可验证的下一步行动」**；大多数产品的火力集中在求职执行环节（简历、投递、面试）。

**我们的差异化**：**每条建议都有依据、能点开核查，不确定的明确说不确定**。通用 AI 也能聊职业规划，但它说得漂亮却没法验证，甚至会编。我们把"依据可查 + 不乱说"做成硬机制。

## 三、产品长什么样（5 分钟版）

**核心设计一：用户不需要自带目标。**

```
第 1 步   回答 6-8 个问题（专业、年级、学过什么、会什么、兴趣、约束）
              ↓
第 2 步   系统按固定规则打分，给出 3 个候选方向 + 每个的匹配理由
              ↓
第 3 步   用户选一个方向
              ↓
第 4 步   看到差距：已有 / 待补 / 待验证
              ↓
第 5 步   拿到一项两周微任务——它要验证你自己的哪个假设
              ↓
        （每一句关键结论都能点开看证据来源；
          不确定的明确标"未知"或"团队判断"，不糊弄）
```

**核心设计二：三条硬约束保证 AI 不乱说**（这是我们的立足点，不是口号）：

1. 每条岗位事实在资料库里都有**唯一编号**；AI **只能引用已存在的编号**
2. 资料库里没有的，AI 必须说「未知」或标「团队判断 + 置信度」——**不许自己编，也不许生成链接**
3. 程序在展示前**自动检查**：出现资料库外的说法就拒绝显示

**演示故事（9/28 用这个）**：
> 大三学生小A，暑假要投实习，在数据分析、运营、供应链分析之间犹豫，不知道现在开始补什么来得及。
> → 回答 8 个问题 → 系统按规则打分给出 3 个方向，供应链分析排第一（系统说明分数由什么构成）
> → 小A 选「供应链分析」→ 看到差距：已有（Excel/线性代数）/ 待补（SQL、库存优化基础）/ 待验证（是否接受与数据独处）
> → 拿到两周微任务：「用公开数据集做一个进销存分析并写 300 字结论」——**说明它要验证的假设是「是否享受从数据里找答案」**
> → 每条结论可点开看证据编号和来源；没把握的地方明确标出来

## 四、Demo 做什么、不做什么

**保底链路（5 步，D4 没跑通时唯一要保的）**：

| # | 环节 | 一句话说明 |
|---|---|---|
| 1 | 现状采集 | 6-8 个问题，每题都对应一个评分字段或未知项 |
| 2 | 规则评分 + Top 3 | 固定规则打分（可复现），AI 只负责解释分数 |
| 3 | 选方向 + 差距分析 | 已有 / 待补 / 待验证 |
| 4 | 两周微任务 | 说明它要验证用户的哪个假设 |
| 5 | 证据类型 + 来源 ID | 每句关键结论带证据标识，可点开 |

**增强项（保底跑通后再加，按此顺序）**：换方向重生成 → 方向同标准比较表 → 分学期完整路径（演示用预置案例展示）→ 界面三色/分级呈现。

**明确不做（防止范围膨胀，想做记入 v2）**：
上传简历解析、AI 面试、简历编辑、社区/社交、学校管理后台、长期记忆、完整测评体系、大规模数据爬虫、其他年级节点。

> **砍单规则现在自洽了**：D4 结束时若保底 5 步未跑通 → 冻结一切增强项；若仍未通 → 走预置案例降级演示（见第六节），不当场赶工。

## 五、分工：三块，块内自己协调，块间只交三次东西

**分组原则**：按"需要多频繁对齐"来分。**需要频繁讨论的人放在同一块**，块与块之间只交接成品。

```
┌─────────────────────────────────────────────────────────┐
│  内容块：tmj + lsy + 第6位（在职，异步）                    │
│  产出：3-4 个方向的能力证据库（每方向 5-8 条，每条可溯源）    │
├─────────────────────────────────────────────────────────┤
│  技术块：Bruce + xrr                                     │
│  产出：能跑的应用（规则评分 + 引用约束 + 校验层 + 界面）     │
├─────────────────────────────────────────────────────────┤
│  表达块：lx                                              │
│  产出：演示脚本 + 老师访谈 + 汇报材料 + 用户测试            │
└─────────────────────────────────────────────────────────┘
```

| 成员 | 你在哪块 | 你要交付什么 |
|---|---|---|
| **tmj** | 内容块 | **D1 交数据契约**：字段名/类型/必填项/允许值/证据格式/缺失时怎么处理/一个完整样例——这张表同时是验收标准。外加 2 个样板方向 |
| **lsy** | 内容块 | 按契约填 3-4 个方向 × 每方向 5-8 条能力证据；**每条能力结论至少挂 2 个来源**，注明适用范围和日期 |
| **第 6 位（在职）** | 内容块 | 异步三件事：① 你自己的职业路径经历 1 份 ② **D2 逐条审核 tmj 的 2 个样板**（写清改了什么、为什么）③ 演示时讲 3 分钟「真实从业者怎么说」 |
| **Bruce** | 技术块 | **集成负责**：AI 接入 + 校验层（扫描引用编号是否真实存在）+ 主链路装配（对「整体能跑」负全责） |
| **xrr** | 技术块 | **输出协议与质量门槛负责**：证据编号规则、提示词里的引用约束、校验规则、Streamlit 界面 |
| **lx** | 表达块 | 演示脚本（先出只用保底 5 步的版本）+ 访谈 2-3 位就业指导中心老师 + 汇报材料 + 组织 1-2 名非组员做最终测试 |

### 5.1 为什么这样分

- **xrr 负责输出协议而不是事后检查**：你的优势是严谨的证据标准，把它直接设计进数据格式和提示词里，比做完了再来挑错有效——标准和生产是同两个人，不存在「标准晚于产出」
- **内容块三个人并行**：填证据是并行度最高、最不需要协调的活，正好适合容纳一位时间不可控的在职成员；而且第 6 位的审核放在**批量填写之前**（审样板），比全部填完再返工便宜得多
- **lx 单人在表达块**：写脚本、访谈、做 PPT 都是独立作业，不会被别人阻塞；他还兼任最终用户测试的组织者

### 5.2 块间只交接三次（其他时间互不打扰）

| 时点 | 交什么 | 从 → 到 |
|---|---|---|
| **D1** | 数据契约（tmj 出，Bruce 花 10 分钟确认「这些字段我的程序用得上」） | 内容块 → 技术块 |
| **D3** | 填好的证据库（3-4 方向 × 每方向 5-8 条，含来源链接） | 内容块 → 技术块 |
| **D5** | 可跑的应用（技术块交，lx 拿去给非组员做测试） | 技术块 → 表达块 |

**除此之外，各块内部自己安排节奏，不需要向其他块汇报进度。**

### 5.3 分工怎么定

由 Bruce 根据每位成员提交的「每天可投入时间 + 擅长/想做的方向 + 最不想做的」统一指派。**每人只对自己那一行有当场异议权**。不做全员投票：6 天窗口等不起一轮讨论，且分工质量取决于"谁会什么、能投多少"而不是人数。

| **9/28** | — | — | 交付 |

**两条铁律**：
1. **D4 结束保底 5 步未跑通，冻结一切增强项**；仍未通就走预置案例降级演示，不当场赶工。
2. **合格标准**：① 系统不输出资料库外的事实；② **一个不是我们组的人，不需要我们解释，就能独立走完 10 分钟，并说清三件事——我被推荐了什么方向、我还不确定什么、接下来两周做什么**。界面好不好看不在验收标准内。

### 6.0 Demo 是给组员讨论用的，不是给评委打分的

**目标不是「演示得漂亮」，是「每个人都能自己判断这个方案可不可行」。** 三条要求：

1. **D4 必须交「环境可复现」文档**——依赖清单、一键启动脚本、API key 申请方式。**每个人都要能自己跑一遍**，否则讨论退化成看一个人表演，其余人无法真正判断。
2. **D6 是全员走查，不是彩排。** 走查时每人要能回答三个问题：主链路通不通？证据约束真的在起作用吗？哪一块最弱？
3. **降级方案（预置案例）的用途**：防组员自己试用时 API 限流或额度耗尽，不是防现场翻车。

### 6.1 用户测试怎么做（D5，lx 主导）

- **不解释产品、不代填、不提示**——测试者必须能自己开始
- 记录三件事：完成率 / 卡在哪 / 能否说出「方向 + 不确定什么 + 两周做什么」
- D6 只修影响这三件事的问题，其余记入 v2

### 6.2 降级方案（D5 前备好）

准备一份**无模型的预置案例**（小A 的完整走查结果，含全部证据编号）。用途：组员自己试用时 API 限流或额度耗尽（学生额度很容易用完），可以直接走预置案例继续讨论，不阻塞判断。

## 七、常见疑问

**Q：AI 会不会瞎编岗位要求？**
有三道关卡拦着：① 所有岗位事实有唯一编号，AI 只能引用已存在的编号；② 没有的必须说「未知」或标「团队判断」，不许编也不许生成链接；③ 程序在展示前自动扫描，出现库外的说法就拒绝显示。

**Q：为什么终点是「两周小任务」而不是完整学期路径？**
因为路径的每一步都要挂可溯源证据，6 天内做不到可信。两周微任务是同一个价值（下一步做什么）在**证据守得住的尺度上**的版本，也更好验收。完整路径是 v2 主线，Demo 里用预置案例展示产品走向。

**Q：为什么不做简历、面试功能？**
那些是红海，且 6 天做不深。我们的价值在更早的方向决策。列入 v2。

**Q：为什么从大三开始，不是大一？**
产品愿景是覆盖大学全程，但 Demo 只做一个点，选痛点最强的：大三学生暑假要投实习，有真实截止日期，方向没想清楚的代价最直接。大一阶段列入后续节点。

**Q：我的部分做不完怎么办？**
按砍单线走：D4 砍增强项，D5 砍界面美观度，D6 只修阻断性问题。先保保底 5 步。

**Q：我不同意这个方向？**
现在提，不要在 D4 提。讨论会上把异议说完，定了就全力做。

1. **每天真实能投入几小时**（决定六天计划要不要再砍）
2. **你擅长什么、最不想做什么**（Bruce 据此最终指派——是决策不是投票，但有异议权）

**任务指派说明**：分工由 Bruce 统一决定，依据是各位提交的时间与擅长项，以及各环节的依赖顺序。不做全员投票——6 天窗口等不起一轮讨论，且分工质量取决于信息（谁会什么、能投多少）而不是人数。**但每个人对自己那一行有当场异议权**，Bruce 会调整。
