# 岗位覆盖、可解释匹配与 O*NET 接入 Implementation Plan

**Goal:** 建立培养方案对应的岗位覆盖台账，增加可追溯的多企业 JD，替换按能力项数排序的基础匹配，接入官方 O*NET 快照与有引用的检索。

**Architecture:** 沿用 Python / FastAPI / SQLite 单体。国内 JD 决定本地岗位证据及准入；O*NET 作为版本化职业知识参考。推荐分成阶段与条件检查、全量候选比较、证据归一化排序、有限多样性重排。所有方法均为待真实用户校准的初始规则。

**Tech Stack:** Python、SQLite FTS5、requests、现有结构化抽取与语义核验服务。

用户已授权本阶段实现，继续在含前序未提交实现的工作目录完成，不重置历史修改、不另行开启会话或委派代理。

## 任务与验收

1. **岗位覆盖与采集**：新增 `coverage.py`、采集命令和来源清单；5 个培养方向映射 14 个候选岗位族，按实习/校招分别显示来源、去重近期 JD 数、雇主数和缺口。实际采集成功与核验通过分别统计；禁止为满足配额降低准入要求。
2. **O*NET**：从官网确认当前版本及许可，保存全量公开表格快照、校验和与清单；导入职业、任务、能力、兴趣及量表信息，保留美国语境、采样与量表字段。岗位族与职业编码映射标为本地候选映射，不能冒充官方跨国对应。
3. **匹配规则**：按雇主平衡的要求覆盖计算证据维度；缺失信息保留区间，不按能力不足扣分。学历冲突只约束特定 JD，不推断整个岗位族；优先保留有本地证据的可探索方向。MBTI 不参与排序；O*NET 兴趣暂作解释参考，问卷未校准前不加权。
4. **检索与报告**：按岗位族候选职业映射过滤 O*NET 检索，返回精确表名、版本、行标识及原文引用；用确定性文字生成职业参考，接入学生报告与管理端覆盖接口。检索失败不编造引用。
5. **质量验证**：回归测试覆盖长 JD 偏差、多数雇主偏差、未知与缺口、资格冲突、多样性、O*NET 量表及引用；实际运行数据采集/导入，输出覆盖缺口与基准结果。运行现有自动测试和浏览器检查。

## 方案取舍（ADR）

- **内容与知识规则（采用）**：适合只有 15 人试点、缺少行为历史的阶段；可复现、可解释。排序参数是工程假设，需后续校准。
- **协同过滤（暂缓）**：依赖充分的交互矩阵，目前缺少数据；学生点击不等于适合某岗位。
- **双塔/深度排序（暂缓）**：未来有足够标注和行为后可用于候选召回、学习排序；当前 14 个岗位族可全量比较，无需为规模优化牺牲可解释性。
- **纯 LLM 决定排名（不采用）**：难复现且易将推测当事实；AI 用于拆解和核验，引用与排序由程序约束。
- **多样性**：只在同一证据等级、相近相关性的候选间做轻量重排，不能把缺乏依据的方向抬成推荐。
