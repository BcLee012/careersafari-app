# 岗位覆盖、匹配与 O*NET：本阶段实现说明

## 当前产品边界

首批围绕现有南京大学管理科学与工程 2026 级培养方案的五个方向，维护 14 个候选岗位族。实习与校招分开，共 28 个覆盖单元。对应关系是团队的候选假设，培养方案并不保证这些就业去向。目录及任务定义分别在 `coverage.py`、`taxonomy.py`。

学生先填写个人画像，再比较通过门槛的多企业岗位画像。岗位资料用于职业探索，不代表职位当前在招。持续陪伴与投递暂不实现。

## 推荐系统可以借鉴什么

采用推荐系统的候选生成、评分、重排结构。目前目录只有 14 类，直接全量比较，比训练大规模召回模型简单。没有足够交互历史时，用内容与知识规则启动。

- **条件检查**：只做有依据的阶段、学历等判断。专业范围模糊、日期未知、实际工作方式未知时保留待确认。当前不保证覆盖地域、到岗日期、全部证书等投递条件。

学生的在读学历不等于已取得学历。JD只写“硕士及以上”、没有说明是否接受在读/预计毕业时，保留资格待确认；明确要求已取得学历/学位且存在冲突时才排除对应JD。研一演示案例据此保留数据分析实习的第三家来源，避免将文字歧义扩大成整个方向不适合。
- **岗位证据准入**：每个岗位族与阶段至少 6 份近 24 月的有效去重 JD、3 家独立企业；共同能力至少 2 家支持。原文、来源、任务分类、需求引用和语义都须通过。
- **个人证据比较**：专业/工具经历优先于仅有通用能力交集；再按归一化的要求权重比较证据，避免要求写得多的岗位自动胜出。
- **方向偏好**：已填写的培养方向兴趣用于证据相近时的比较，对应关系仍是本地假设。
- **多样性重排**：同一证据等级、相近分数且偏好状态相同的方向，优先提供不同能力组合。不能抬高未准入方向。

互联网推荐的行为数据可以帮助预测点击；职业探索还要考虑资格、能力证据和学生真正想完成的任务。点击更多不能直接当作更适合。当前没有足够数据训练协同过滤、双塔或深度排序，也没有证据宣称它们迁移到本项目就效果更好。

方法依据：[Google 推荐结构](https://developers.google.com/machine-learning/recommendation/overview/types)、[内容推荐](https://developers.google.com/machine-learning/recommendation/content-based/basics)、[重排](https://developers.google.com/machine-learning/recommendation/dnn/re-ranking)、[协同过滤的局限](https://developers.google.com/machine-learning/recommendation/collaborative/summary)。这些资料支持架构选择，不证明本项目排序参数已有效。

## 目前使用的公式与局限

对每项能力，先计算各企业内部去重 JD 的出现比例，再对企业取均值。优先/加分要求的出现强度暂计 0.5，普通要求计 1。同一 JD 重复提及不会重复加权。

个人证据下界 =（提供实践描述及作品引用的要求权重 + 0.5 × 课程/自述要求权重）÷共同能力总权重。

信息上界在下界基础上加入未知项及尚未核实的自述部分。用户明确表示不会的项才是缺口；缺失资料保持未知。下界和上界是证据信息量，不是熟练度、匹配百分比或录用概率。前端不展示百分比。

0.5 和多样性窗口 0.08 是初始工程参数。研究框架不能为这些数值背书；需要真实样本校准。提供材料仍不证明真实性、个人贡献或熟练程度。

通用能力包括沟通、协作、抗压、书面表达和英语。只有这些交集时，报告说明“通用能力有交集，专业经历待补”，不直接确定职业方向。

学生表单同步补充了采购/供应商管理、产品需求、行业研究、风险合规、数据整理与数据工程等专业经历选项。能力名称与受控 ID 对应，未填保持未知；更换培养方向时已填写材料仍保留。

MBTI 不参与过滤或排序。现有 18 题兴趣问卷未经量表验证，暂不用于排序；价值观与本地工作方式尚缺可靠岗位依据，也不编造对应分数。

## 自动证据流程

企业官方接口/页面 → 保留响应与原文快照 → 校验岗位身份、阶段、发布日期 → AI 按任务/产出归类与拆解 → 程序检查引用 → AI 逐项核验 → 最多一次修正 → 通过或隔离。

首轮四个来源为字节跳动、京东、百度、美团；后续新增中金、中信证券、开源证券、国投证券、美的、顺丰，字段规则见 [行业来源说明](行业岗位来源.md)，当前状态见 [项目进展与续接](项目进展与续接.md)。企业集团按一个来源企业计数；京东详情是 POST 接口，保留接口 URL 与原始响应，页面链接前往官方岗位目录并显示岗位编号。发布日与更新日分开，更新日不能补成发布日。

`collect_evidence.py` 优先补缺失企业及 JD 数，并跳过已核验/待确认的来源，避免每次浏览或重新运行重复消耗模型额度。队列中的标题提示仅用于安排采集，正式分类仍须来自任务证据。

实跑发现算法研发误归分析、通用后端误归信息系统等问题。因此补充了任务定义、目录外边界和补充审查命令 `audit_families.py`。补充审查不自动换标签；有疑点的旧记录转为待确认，保留旧结论和审查轨迹。AI 审查可能仍有错误；通过状态不是职场专家认可。

## O*NET 与 RAG

[O*NET 官方数据库](https://www.onetcenter.org/database.html)当前接入 31.0。全量 45 张 CSV 表保留为本地快照，1,120,006 条原始记录；索引只覆盖与本地候选对应的 19 个美国职业、10 张知识表，共 13,490 行。

保留职业编码、原始任务、量表 ID/名称、数值、样本量、抑制标记、日期和来源。引用格式 `ONET-31.0:表名:记录序号`；序号从表头后的第 2 条开始按 CSV 逻辑记录编号，含换行的单元格不按文本物理行计算。

流程是岗位族候选编码过滤 → 中英受控词扩展与 FTS5/BM25 检索 → 最多 4 条中文解释 → 引用 ID 校验 → 第二次 AI 原文支持检查 → 缓存结果。没有资料或检查失败则展示资料/失败原因，不补写答案。

此版本已经是真实检索加生成的 RAG；目前使用词法检索，尚未添加向量检索与学习重排。中文问题只覆盖受控词扩展范围，复杂问法可能检索不到。应先记录失败查询，再决定是否增加多语种向量召回。

美国职业与国内实习/校招的对应不是官方一一映射。O*NET 不填补国内 JD 配额，不转为国内学历门槛，也不直接为学生能力打分。按 [CC BY 4.0 许可](https://www.onetcenter.org/license_db.html)展示归属、改动说明及未获 USDOL/ETA 认可的声明。

## 团队如何继续运行

在仓库根目录运行：

```sh
app/.venv/bin/python app/import_onet.py
app/.venv/bin/python app/collect_evidence.py --discover --register-raw --ingest-limit 60 --workers 3
app/.venv/bin/python app/audit_families.py --apply
app/.venv/bin/python -m unittest discover -s app/tests -p 'test_*.py' -q
```

采集与核验使用配置中的业务数据库，启动前应留存备份。大体积快照、索引和采集缓存位于已忽略的 `app/data/onet/`、`app/data/evidence/`，需重新下载或另外保留；不在代码仓库中假装已分发。

管理端新增完整覆盖台账和有引用的职业问答，学生报告增加美国职业参考。来源缺口与实际验收结果见同目录下的评估报告。未满足门槛的方向仍是候选，不能包装成已经全面覆盖。
