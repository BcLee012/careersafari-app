## 实际修改

1. **恢复来源信息。** 保存原始 HTML、正文、最终地址、采集时间。百度适配器检查官方主机、职位 ID、详情招聘阶段与路由一致性，再读取企业、发布日期和更新日期。公司和阶段不再要求必须出现在清洗后的正文里。发布日期使用明确的 publishDate，updateDate 单独记录。
2. **引用使用编号。** 初次尝试仅增加多段引用数组，真实模型仍拼接了职责。随后改为提供 S 编号原文片段，由模型选择编号，程序恢复完整原文并记录位置；未知编号、引用不匹配仍被拦截。原始失败记录保留在相邻的 2026-10-11-repaired-jd 目录。
3. **保留语义核验。** 选对引用编号不自动等于正确结论；模型仍须逐项核对岗位分类、任务、要求、类别和程度。全部支持后才入库。
4. **提前排除社招。** 可靠的官方阶段字段用于范围判断；来源与正文明确阶段冲突则隔离，不强行归类。
5. **减少无效重复。** 服务器采集结果可以复用，缺失来源信息不让 AI 猜；可修正的模型问题最多修正一次。来源字段变化使缓存失效。记录模型输出、来源覆盖、核验意见、耗时与供应商提供的用量。
6. **补充动态采集。** HTTP 正文不足时启用一次可选 Playwright 浏览器采集，限制并发、时间、体积、请求数量并逐跳检查来源。本环境有运行库；其他部署环境需配置相应依赖。备用通道不保证每个站点都能取得正文。
7. **改善页面状态。** 报告区分无输入、检查未通过和岗位画像样本不足；异常队列显示名称、公司、来源和中文原因，采集失败可重新采集。旧流程数据保留可浏览，需要按新规则重新检查。

## 当前能说明什么

真实 JD 已经能进入“采集 → 来源核对 → 提取 → 引用检查 → 语义核验 → 入库”的完整流程，社招能自动分流。这批样本尚未独立评估模型分类、要求拆解与语义核验的准确率，不能把模型全部同意解释成事实准确率 100%。

**尚不能形成正式学生岗位匹配。** 4 份入库 JD 全部来自同一企业，分属不同岗位族和招聘阶段；部分原始发布日期较早。当前按明确的发布日期保守计入近24个月门槛，更新日期留存但没有代替发布日期。仍不满足每岗位族×阶段的“6份有效去重 JD、3家企业、共同能力至少2家企业支持”。

因此学生报告显示“证据待补充的候选方向”，没有把入库成功误当成完整岗位画像。下一阶段需要补充不同企业的实习／校招来源，并做少量人工基准抽查。
