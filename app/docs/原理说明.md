# CareerSafari 原理说明

> 这份文档回答三个问题：**为什么这样做、每层解决什么、边界在哪里。**
> 写给想判断「这个方案可不可行」的人，不只是想用的人。

---

## 一、要解决什么问题

调研数据（均来自 `参考资料/`，可溯源）：

| 数据 | 来源 |
|---|---|
| **57.6%** 认为「找不到自身优势、定位模糊」是最大困难 | 智联《2026 职场人求职盲区调研报告》 |
| 未拿到 Offer 的毕业生中 **36.2%** 归因于「过度迷茫、不清楚自身适配方向」 | 智联《2024 大学生就业力调研报告》 |
| 仅 **22.9%** 的大学生有明确职业规划 | 中国青少年研究中心 |
| **64.8%** 表示不清楚市场情况 | 中国青年报社社会调查中心 |

痛点排序很清楚：**自我定位 > 了解市场 > 缺行动方案**。而市面产品的火力集中在求职后端
（简历、投递、面试），前置的「我是谁、我去哪、差什么」几乎无人认真做。

**目标人群**：大学初期（大一 / 研一）· 方向未定型。共同点不是学历层次，是
「还没形成稳定职业方向，需要提前规划」。

---

## 二、核心主张：让不可验证的建议变得可验证

通用 AI 也能聊职业规划，但它说得漂亮却没法验证，甚至会编。学术证据：
- RCT 显示 GPT-4o 生涯反思智能体比静态日志更**降低决策承诺、增加疑虑**（arXiv 2609.19635）
- N=6474 RCT 显示 **79%** 用户听从 AI 职业建议但**无持续福祉改善**（arXiv 2511.15352）
- 谄媚效应：情绪表达显著提高模型对「过早决策」的背书（arXiv 2608.27465）

所以本产品的定位不是「更聪明的建议」，而是**每条建议可核查、不确定处明说**。

## 三、四层架构

```
┌─ 第 1 层  确定性计算 ────────────────────────────────┐
│  match.py     用户能力 × 岗位要求 → 四类差距            │
│  可复现、可测试、可逐条解释。两次提交结果必然一致。       │
├─ 第 2 层  模板化叙述 ─────────────────────────────────┤
│  advice.py    把差距翻译成行动项                        │
│  仍然是确定性的。每条行动带「验证什么假设」「成本」「来源」 │
├─ 第 3 层  LLM 润色（可选） ──────────────────────────┤
│  只允许引用前两层的 item；生成后校验所有课程名与 req_id  │
│  真实存在，否则整段丢弃回退第 2 层。绝不放大模型决策权。   │
├─ 第 4 层  数据契约 ──────────────────────────────────┤
│  schema.py / curriculum.py                             │
│  能力 Taxonomy + 培养方案课程映射 + 岗位族，全部人工整理  │
└──────────────────────────────────────────────────────┘
```

**为什么这样分**：如果让 LLM 直接生成建议，它会把不存在说成存在、把「团队判断」说成
客观事实、并且每次结果都不一样。前两层把事实钉死，第三层只负责措辞。

## 四、五个关键设计决策

### 1. 原子化判据：拆到「能否被单独验证」为止

「熟悉 SQL」不可验证；「能独立编写多表 JOIN 查询」可验证。

这个判据决定后端匹配能不能做——拿不可验证的条目比对用户自评，比出来的数是假的。
实测对比（同一则 JD）：

| | 规则基线 | LLM 拆解 |
|---|---|---|
| 条数 | 5 | 8 |
| 软能力 | 1 条混在一起 | 拆成 3 条独立 |

### 2. evidence_span 回查（生成后校验）

每条需求必须附 `evidence_span`（JD 原文逐字复制的支撑句）。程序归一化后回到原文做
子串匹配，匹配不上的标记「无原文支撑」并降级为 `team` 置信度 0.3，**不当作外部证据采信**。
全部不通过则整体拒绝入库。

这是「系统不输出资料库外的事实」的最小可运行实现。118 个岗位 1304 条需求的实测通过率
**99.3%**（1295/1304）——剩下 9 条正是被 LLM 改写后找不到原文支撑的。

### 3. 先约束后偏好

采集顺序：**硬约束 → 能力 → 兴趣 → 价值观 → 未知**。

硬约束是筛子不是偏好，它直接决定可行范围且几乎零成本获得。反过来问会得到一堆
无法用于筛选的信息。培养方案的中期考核/开题/答辩就是最典型的约束——
它们不关心你的兴趣，只决定你还有多少时间。

### 4. 自述与证据分离

能力项分「有证据」与「仅自述」两栏，声称有证据却写不出具体来源的自动降级。

不区分的话，后端匹配就是在拿用户的自我感觉对企业的硬要求。

### 5. 未知是一等公民

`unknown` 不是失败状态，是合法输出。系统不许猜。

这是与通用聊天机器人最本质的分界线，也是整个产品唯一真正稳定的差异点。

## 五、三个统计陷阱及防护

### 小样本陷阱
只有 2 条可比对需求的岗位，2 条全中就得到 100% 覆盖率，从而打败有 15 条要求、缺 3 条的
大样本岗位。这不是「证据更充分」，是题目更少。

**防护**：要求 `n_comparable >= 5` 才能参评，不足的标记「样本不足」而不是给虚高百分比。

### 岗位族碎片化
LLM 对同一类岗位给出不同名字（商业分析师 / 战略商业分析师 / 商业分析Leader），
直接当独立岗位会让统计虚高、结果列表碎成一地。

**防护**：受控岗位族词表归一化，同族只保留证据最强的代表，展示族内样本数。

### 通用能力霸榜
「沟通」「协作」「英语」出现在大量 JD 里，按被需数量排序会挤掉具体可补的缺口。

**防护**：硬缺口优先于软能力；培养方案**必修课**排最后（那是既定安排，不构成建议）；
软能力单独分区并明确「选课无法获得」。

## 六、数据资产

| 资产 | 规模 | 来源 |
|---|---|---|
| 岗位族 | 10 个受控族 | 人工定义 |
| 能力 Taxonomy | 22 项，含别名表 | 人工整理 |
| 培养方案映射 | 16 项能力 → 课程 | `参考资料/` 培养方案人工整理 |
| 岗位库 | 118 个岗位 / 1304 条需求 | 字节跳动校招官网（P1） |

**培养方案映射是本产品相对通用 AI 唯一的结构性优势**：通用模型不知道南京大学工程管理学院
管科学硕开什么课、哪个学期开、几个学分。这是本地知识对通用知识的降维打击。

诚实边界：有 6 项能力在培养方案内**没有**对应课程（Excel、指标体系、三个软能力等）。
明确留空并说明，而不是硬凑一门课。

## 七、已知边界（主动交代）

1. **不做匹配算法之外的推荐**。排名由确定性规则产生，公式公开：
   `verified_coverage = 有证据的能力要求数 ÷ 可比对的能力要求数`。
   这是**团队定义的启发式指标**，不是标准化测评分数。
2. **规则权重本身是团队判断**，已在界面标注，不伪装成客观。
3. **MBTI 只作辅助标签**。重测信度约五成、对绩效预测力弱（Pittenger 1993），
   界面强制展示该局限。
4. **不做微调、不做多 Agent**。样本量不够，单链已够。
5. **合规边界**：以个人身份在中国大陆无法合规公开运营招聘信息站
   （个人 ICP 备案禁止涉及招聘类内容；经营性网络招聘服务需《人力资源服务许可证》）。
   本原型定位为「职业认知与决策支持工具」，不做岗位聚合、不做投递撮合，本地运行。
6. **URL 采集的现实**：主流招聘官网是 JS 渲染 SPA，本地 `requests` 抓不到正文。
   这是技术限制，不是策略选择。
7. **LLM 非必需**。确定性引擎是主路径，LLM 只润色措辞。配额耗尽时功能完整可用。

## 八、怎么验证这套东西真的有效

不需要信我们的话，按顺序做：

1. **跑同一份问卷两次**，确认方向排序一致（确定性引擎保证）
2. **把一项能力从「仅自述」改成「有证据」**，看该方向覆盖率变化
3. **点开任意一条需求的 evidence_span**，回 JD 原文核对是否逐字存在
4. **把「高频加班」设为不可接受项**，看哪些方向被排除、排除理由是什么
5. **问一个资料库外的问题**（如「我该转码吗」），看系统是否说「未知」而不是编

第 3 条是最硬的：它验证的是「系统不输出资料库外的事实」这句话是不是真的。
