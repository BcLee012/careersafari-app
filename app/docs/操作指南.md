# CareerSafari 操作指南

> 面向第一次使用的人。目标：**10 分钟内独立走完，并能说出三件事**
> ——我被推荐了什么方向、我还不确定什么、接下来两周做什么。

---

## 一、启动

```bash
cd app
./run.sh
```

首次运行会自动用 `uv` 创建 Python 3.12 虚拟环境并安装依赖，无需手动步骤。
启动后浏览器打开 **http://127.0.0.1:8765/**。

| 情况 | 处理 |
|---|---|
| 提示「写操作未启用」 | `app/.env` 里 `ADMIN_TOKEN` 为空。删掉那一行重启，服务端会自动生成 |
| 顶栏显示「LLM 未配置」 | `.env` 缺 `STEPFUN_API_KEY`。功能仍可用，JD 拆解会走规则基线 |
| 顶栏显示「LLM 就绪」 | 正常，JD 拆解与建议润色都会调用模型 |

## 二、页面一：用户画像（五步）

### 第 1 步 · 硬约束
填专业、年级、倾向方向、期望工作地、**必须落地的时间点**、不可接受项、实习目标。

- 时间点和地域都可以选「我不确定」——会登记为 `unknown`，系统不会替你猜
- **培养方案的硬节点**（中期考核/开题/答辩）本质上也是硬约束，只是这里由时间点体现

### 第 2 步 · 能力（两栏）
左栏「通用可迁移」，右栏「目标岗位相关」。**切换左上角的研究方向时，右栏预设会跟着变。**

每项操作：
1. 点星打自评分（1–5）
2. 想要标记「有证据」，点「有证据？」按钮，然后**必须**写清是哪门课/哪个项目/哪段实习
3. 点了「有证据」却不写内容 → 提交时自动降级为「仅自述」

> 这一步是整个产品最核心的设计：**「你说你会」和「你做过」是两种证据强度。**

### 第 3 步 · 兴趣
RIASEC 六型各 3 题，共 18 题，按真实反应作答。

- **全填一样的分不会得到兴趣码**——系统会明确说「各维度未分化」，而不是按代码顺序编一个
- MBTI 可选。填写前必须勾选信度确认（重测信度约五成、对绩效预测力弱）

### 第 4 步 · 价值观
把 **100 分分配到 6 个维度**。实时显示合计：刚好 100 变绿、超出变红、不足变黄。

> 自由打分时人倾向于「什么都重要」，六个 90 分等于没填。强制分配才能逼出真实取舍。

### 第 5 步 · 未知项
先勾选候选（「我是否真的喜欢这个方向」「我这个年级补技能是否来得及」…），也可自定义。

**「我不确定」是合法答案。** 系统会把它登记为 `unknown`，不会猜一个答案填上。

### 生成
点「生成求职意向定义卡」，会一次产出两张卡：

**求职意向定义卡** —— 你是谁
- 硬约束表（每项标注 `user_stated` / `unknown`）
- RIASEC 码 + MBTI 辅助标签
- 能力分「有证据」与「仅自述」两排
- 显式未知清单
- **诚实性摘要**：几项有证据、几项仅自述、几项未知
- 输入一致性警告（如人设选大一但年级填研一）

**求职与学习建议** —— 你该做什么
- 顶部结论条：证据强度、匹配/自述/缺口计数
- 方向结论：按岗位族排序，带覆盖率条形图
- 可借培养方案弥补的硬缺口（带课程名、学期、教师、学分）
- 只能靠实践获得的能力
- 接下来两周做什么（每项带「验证什么假设」和「成本」）

## 三、页面二：岗位知识库

### 三种采集入口
| 入口 | 用途 |
|---|---|
| 手动粘贴 | 主力路径。粘贴 JD 原文，保留原始分行和标点 |
| URL 采集 | 补充。走域名白名单 + robots.txt + SSRF 校验 |
| 文件导入 | 批量。支持 txt / md / html / docx / pdf |

URL 采集的说明：主流招聘官网是 JS 渲染的 SPA，本地抓不到正文——这是技术现实。
抓不到时界面会明确说明并提示改用手动粘贴。

### 拆解与入库
1. 点「拆解为原子化需求」
2. 查看**生成后校验**结果：每条需求的 `evidence_span` 是否在 JD 原文中找到
3. 没找到的标红为「无原文支撑」，降级为团队判断
4. 填标准化岗位名和行业，点「确认入库」

**LLM 输出永不直接进库，必须人工确认。**

### 浏览与筛选
岗位库支持：关键词搜索、硬/软要求过滤、证据等级过滤、岗位族 chips 过滤。
鼠标悬停在需求标签上可看它对应的 JD 原文片段。

## 四、命令行工具

```bash
# 端到端演示案例（不依赖浏览器，输出完整报告）
.venv/bin/python demo_case.py

# 灌入种子数据（3 个管科对口岗位）
.venv/bin/python seed.py

# 采集真实 JD（字节跳动校招，P1 可信度）
.venv/bin/python collect_bytedance.py --limit 15
.venv/bin/python collect_bytedance.py --extract 50 --workers 3
```

`--extract N` 会对 N 条未解析 JD 跑 LLM 拆解。每条 30–50 秒（推理模型固定产生
10–14k reasoning token），建议 `--workers 3`。

## 五、常见问题

**Q：为什么我的方向覆盖率都很低？**
A：因为你的能力项大多是「仅自述」。把其中一两项变成「有证据」，覆盖率会明显变化——
这正是系统在逼你区分「会说」和「做过」。

**Q：为什么某个方向被排除了？**
A：只有 JD **明确**写到加班/996/出差/驻场时才排除。只出现「抗压」「节奏快」这类
通用套话时**不排除**，只提示你核实。错杀比漏报危险。

**Q：为什么有些能力没有推荐课程？**
A：培养方案内确实没有对应课程（软能力、指标体系这类）。系统明确说「无对应课程」，
而不是硬凑一门。这是「宁可少写，不可编造」。

**Q：LLM 不可用时还能用吗？**
A：能。确定性匹配引擎是主路径，LLM 只负责润色措辞。不可用时界面会说明，功能不受影响。
